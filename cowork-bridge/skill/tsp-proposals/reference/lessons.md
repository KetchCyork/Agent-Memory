# Lessons and board corrections

Read before drafting. These are corrections made on real drafts.

## platform agnostic bias

2026-07-11: When a proposal opportunity is platform-agnostic or selection-first (client wants help choosing THEN implementing a system — e.g., Meridian Health Partners NEW-9), never let the firm past-proposal corpus bias the draft toward a specific product. Our vault is heavily SAP-weighted (Ameri100/TSP legacy S/4HANA proposals), which pulled an early draft toward presuming S/4HANA Public Cloud as the answer before any selection had occurred, even though the client only asked for help selecting and implementing an ERP/practice-management platform. Rule: before drafting, check whether the opportunity explicitly names a target platform (client-confirmed) vs. is open/advisory (selection phase required). If advisory/selection-first, structure the proposal as Phase 1 Selection (vendor-neutral requirements, evaluation, recommendation) + Phase 2 Implementation (of whichever platform is chosen), and do not name a winner or lean the methodology/scope language toward one vendor. Corrected by board (Chris York) on issue NEW-9 after reviewing a first draft that presumed SAP.

## client facing voice

2026-07-11: For anything client-facing, the firm voice matters. Consult the proposals style profile (10-Profiles/proposals-style) before drafting any client-facing material.
